# Dots minimization

Dots exposes focused operations directly. It has no general router, mandatory
development playbooks or compulsory design/explanation chain. Clarify Requirements
remains distinct from an open Shape Idea discussion. Explorer, Worker and
Adversary are the maintained roles; TOML is canonical and Markdown is generated.

Codex reviewer launches explicitly pass `fork_turns: "none"`. The role description
advertises the requirement; child instructions cannot erase inherited history.
No unsupported TOML history setting is used. Role prose and a read-only sandbox
intent must not be described as a capability boundary the host does not enforce.

## Optional source packages

`wip/artifacts` preserves HTML and editorial authoring with their generators,
source inputs and tests. The retained code-walkthrough template belongs inside
HTML rather than to a removed How skill. Historical PR fixture paths identify
the inspected historical commit and intentionally retain their old spelling.
The walkthrough diagram now fits its actual desktop content area.

`wip/verification` preserves project verification authoring and its attribution.
Neither package is registered, installed or published. Core Dots does not load
them through a hidden fallback. Existing app-specific verification remains owned
by the relevant project.

Do not add the optional packages to the default marketplace merely to make
source validation discover them. The source gate validates them explicitly,
and full checks run the extracted HTML suite from its new location.

## Validation and release

Use the active default skill creator to validate changed skills. Package checks
cover manifests, links and selected invocation policy. The existing history
parser tests remain with their implementation; Handoff-specific tests disappeared
with the removed Handoff helper.

Clarify was compared with its original version using isolated fixtures and
independent agents. The exercised requirements were retained; small-sample
response differences do not establish full behavioral equivalence. Static review
of the pruning and extraction found no supported defects. Neither word counts
nor passing package checks prove runtime savings or installed-loader behavior.

The root gate can remain blocked by unrelated imported REA skill drift; report
that separately instead of skipping checks or modifying REA during this change.
Follow the existing Fleet release procedure for the final version, commit/push,
local and peer refresh, and cloud publication. Source changes alone do not update
installed caches. Cloud archive updates cannot remove retired files; use a
source-deletion-capable workflow or report retained remote files as pending.

Maintainer provenance records retired adapted paths against their final Fleet
revision, while live verification and benchmark material retain attribution.
