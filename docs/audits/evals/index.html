Design plugin: with vs. without

Three tasks, each done twice by the same model: once with this branch's design plugin in the workspace as the team's guidelines, once with nothing. Each agent got an ordinary product brief in its own randomly named folder; nothing told it the run was an evaluation. Graders saw the two outputs as A and B in random order, with no plugin label.

Every criterion carries the prediction made before running: Model knows means both should pass, so that guidance is a cut candidate; Plugin adds means only the plugin run should pass.

What the runs showed

  • The plugin won all three: 7 of 12 vs. 3 of 12 on the build, 6 of 7 vs. 4 of 7 on the review, and 6 of 10 vs. 3 of 10 on the iOS spec. It also produced the review's only zero-false-positive result.
  • The model finds problems on its own. Both reviews found all 14 planted defects, including every subtle one (ease-in, scale from zero, 600ms, same-radius nesting, weight 300 under 18px, uncapped measure, hover-only actions). What the plugin added was calibration: the three always-HIGH defects rated HIGH, a Block verdict, numbered findings and no false positives. Review checklists that only list what to look for are cut candidates. The severity, verdict and scoring rules are earning their place.
  • Knowing isn't doing. Four things I predicted the model would get right without help, it didn't: an ease-in curve on the toast exit, Dynamic Type named for only two elements, safe areas never mentioned, and the save error not shown beside the field. Short reminders of basics still change the output, so the generic principles shouldn't be cut wholesale.
  • Some "plugin adds" rules turned out to be already known: the 0.97 press scale, a custom ease-out curve, undo instead of a confirmation, and toggles labelled for their ON state. Those rules can shrink to a line each.
  • Some guidance didn't land even when it was read:
    • The 300ms ceiling: the plugin build added a 900ms decorative draw and a 600ms fade.
    • Layout-property animation: both builds animated grid-template-rows.
    • The icon cross-fade: both builds swapped text labels instead.
    • The empty state's one next action, and concrete group gaps: both specs missed them.
    The build run read 15 files and the review run 18, so rules that are buried deep get read and then lost.
  • Two regressions in the plugin output:
    • A web unit leaked into the iOS spec ("1024px").
    • The score table never says "out of 10", so a literal grader didn't count it. That's a one-line fix in scores.md.
  • Cost: the plugin runs used about 1.5–1.8× the tokens and 1.4–2.5× the time.
