# Context contract

Use current user instructions first, then authoritative product sources, then
saved product context and finally plugin defaults. A source is authoritative
only for what it defines: a token file controls values; a screenshot records
one state; interview notes record reports, not population-wide facts.

Read the existing product design docs and relevant sources. If the user names a
context home, use it. Do not search unrelated products or copy personal context
into a team repository. Missing saved context does not block a sufficient brief.
Inspect only references needed for this task; disclose unavailable named sources.

Save/update/forget requests belong to `$design-context`. Other skills can use
context without creating a new file. Durable decisions stay in the product's
established documentation when requested, not in the plugin or its cache.

Load [workflow guidance](workflows-guide.md) for research, UX copy,
accessibility, critique, systems or handoff. It points to the full
workflows and defines how they operate on this host.
