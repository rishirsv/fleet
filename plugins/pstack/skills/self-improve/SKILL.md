# Self-improve

Diagnose friction from actual agent work and make the smallest useful durable
improvement. Use the active task unless the user names other work or history.
Counts select evidence to inspect; they do not establish causes or quality.

Read only the branch needed:

- Lessons from the current session: [reflect.md](references/reflect.md).
- Repeated repository mistakes to prevent: [correct.md](references/correct.md).

- Workflow, harness, cost or context problems: [workflow-audit.md](references/workflow-audit.md).
- Repeated work or a broader conclusion: [thread-evidence.md](references/thread-evidence.md).
- A named skill: also [skill-analytics.md](references/skill-analytics.md).
- Agent instruction changes: [instructions.md](references/instructions.md).
- Earlier tasks: [sessions](../../references/sessions.md), including retrieval and resuming prior work.

Reconstruct the request, intended outcome, actions, corrections and checks.
Distinguish verified results from completion claims and observed causes from
plausible explanations. Include successful and contradictory examples. Before
claiming a recurring pattern, fix the window or task set and deduplicate retries
and delegated children under their parent.

For each retained finding, identify the behavior, evidence, consequence,
responsible component, smallest correction and how to verify it. Prefer fixing
ownership or enforcing a deterministic contract over adding another rule.
Use prose only for judgment that a stronger mechanism cannot reasonably enforce.
Name the most useful next action; no reusable lesson is a valid outcome.

Apply supported fixes when requested. Otherwise present concrete proposals
before editing instructions, tools or workflows. Change maintained source
through its owner; propose generated-memory edits for user review rather than
writing memory stores. For a usage report, describe the observed work without
personality claims, and leave state unchanged unless improvements were requested.
