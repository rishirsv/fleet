# Shape idea

Help the user settle an open idea or decision. Preserve supplied goals,
constraints, accepted references and settled choices. Assistant recommendations
remain proposals until adopted. Inspect relevant prior attempts when they
could change the direction.

Map consequential choices as a decision tree. Include both named unknowns
and overlooked decisions about failure cases, affected people, state that must
survive, operation, cost and exclusions. Test a vague rule with a concrete
“What should happen when…?” case.

Identify consequential open choices and their dependencies. Answer factual
questions from available evidence; ask the user about preferences, product
choices and missing information. If an accepted direction conflicts with the
current product, explain the difference before choosing which governs.

Ask answerable questions together in small rounds, most consequential first.
Do not ask a downstream question before its prerequisite is settled. Recommend
a default and explain the useful alternatives and their tradeoffs; ask a simple
preference directly. Teach unfamiliar concepts only as needed for the decision.
Number questions so answers can refer to them. Aim for no more than about five
per round; isolate one when it unlocks most of the tree or needs substantial
explanation. When appearance or behavior determines the choice, read
[Exhibits](references/exhibits.md) and show a scoped, verified comparison before
asking for judgment. Use independent research only when it materially improves
evidence or time; keep unrelated questions moving.

After each reply, update settled decisions and remaining blockers. Keep skipped
choices open and reopen settled choices only when new evidence warrants it.
With permission, infer remaining answers that follow a clear pattern, marking
which choices you made. Do not infer adoption of unresolved choices from a
request to plan or build.

Finish when choices needed for the next requested step are settled or explicitly
deferred and no pending finding could change the direction. Summarize the
outcome, decisions and reasons, exclusions, unresolved choices and next step
using the relevant fields from the
[Idea Snapshot](references/snapshot.md); omit empty boilerplate. If requested,
use [Breakdown](references/breakdown.md) to produce end-to-end, independently
checkable slices with dependencies and acceptance criteria.
Continue an already authorized next step; otherwise stop at the agreed outcome.
