# Workflow and context audit

Compare the observed path with the shortest defensible path available at the
time. Preserve necessary exploration. Inspect repeated work, oversized reads,
manual steps with existing tools, dependent work started prematurely, unchanged
retries and validation that did not change the next decision.

Separate navigation problems from missing access. Use source pointers for the
former and focused diagnostics or access proposals for the latter. Name observed
limitations without inventing an emotional state or blaming a failed attempt
merely because hindsight makes another path obvious.

For context, distinguish loaded instructions, tool results, conversation and
child returns when records expose them. Use bounded queries and retain accessible
source for omitted detail. Keep connected reasoning local and delegate substantial
independent tasks with compact evidence-bearing results. Preserve a short current
state at phase boundaries rather than appending repeated status reports.

Measure testing with paired calls and timestamps when available. Inspect broad
or repeated suites, failure/edit/retest cycles, and checks after completion claims.
Do not infer CPU time from wall-clock span, add overlapping durations as elapsed
time, or treat missing telemetry as zero usage. Per-response input is not a complete
context attribution; cached input is a subset, and cumulative tokens are not occupancy.

For each finding, give the evidence, unnecessary work, likely cause, responsible
component, better path and smallest correction. Apply the task evidence gate
before making a recurring-work claim. No quantified saving without a measured basis.
