# Research behind the companion workflows

These are design inputs, not a dependency to read on every investigation. The
companion workflows synthesize them with the existing REA usage guides and the
actual target's evidence. Commands, engine versions, pricing and showcase claims
from posts are not runtime guarantees.

## Sources read

- [Noisy — ten-step REA article](https://x.com/noisyb0y1/status/2109971347895919070):
  read the full article, code blocks and static images. Useful emphasis: choose a
  feature, trace it, specify it and compare the reconstruction. Embedded demo
  videos were not viewed; no implementation rule depends on their footage.
- [Codila — reusable investigation prompt](https://x.com/0xCodila/status/2109736042991321592):
  read the post, quoted course and full prompt image. Adapted its resumable task
  record and target routing, replacing the fixed questionnaire with context-driven
  intake and immediate inspection.
- [Codila — full course](https://x.com/0xCodila/status/2109623431763292649):
  read the entire article, code blocks and static images. Useful additions:
  follow cross-process features, preserve acceptance criteria and check that the
  comparison harness itself can detect failure.
- [Apriorit — iOS reversing](https://www.apriorit.com/dev-blog/how-to-reverse-engineer-an-ios-app):
  read through all six cases and the conclusion. Inspired Apple artifact, runtime,
  crash and framework routes. Its broad Swift/Objective-C and simulator equivalence
  claims are not adopted; the Apple reference points to primary ABI/symbolication
  guidance and requires evidence for the actual build.
- [Rob Shocks — REA demonstration](https://www.youtube.com/watch?v=OMobTlfjb8s):
  read all 286 English automatic-caption segments, from 00:00 to the final segment
  starting 09:08.440. Useful sections: navigation from strings/callers (02:43),
  a stripped owned-app experiment with held-out source (04:27), and runtime/tool
  limitations (07:49). Caption spellings are not canonical tool names. One observed
  success in a demo does not establish exhaustive equivalence.

X content was retrieved through public FxTwitter payloads when direct X access
failed. Both Articles included embedded Markdown entities; the prompt was read
from its original image. The video transcript came from YouTube's original
English JSON3 caption track. Research copies stay outside the plugin; it ships
original workflow instructions, not copies of the articles or transcript.

## Synthesis choices

The three skills remain separate by outcome: find the implementation, explain or
rebuild its behavior, and compare it to independent observations. Each accepts
raw inputs without making a prepared report a prerequisite. Target-specific
recipes are loaded only when relevant. Existing REA mechanics remain owned by
the main usage skill; these companions choose the next investigation action.

Persistent state records enough to resume without repeating inventory. A feature
path includes data and side effects across boundaries. Verification checks both
the proposed behavior and the mechanism reporting a pass. A successful narrow
comparison does not silently become a whole-product claim.
