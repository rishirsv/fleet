# Fleet's REA package

This plugin is an unmodified source export of
[morluto/rea](https://github.com/morluto/rea), plus plugin manifests and this
`fleet/` directory. There is no additional Fleet investigation workflow.
Use `$reverse-engineer-anything` to start an investigation.

## Ownership

| Location | Owner |
| --- | --- |
| `../src/`, `../scripts/`, `../docs/`, `../.agents/`, package/lockfiles and other imported files | Upstream; never edit here |
| `../skills/reverse-engineer-anything/` | Generated by upstream's normal build, including its version-pinned instructions |
| `../skills/rea-*/` | Exported upstream development skills; only relative documentation links are relocated |
| This directory and the root plugin/MCP manifests | Fleet packaging only |

Upstream distribution manifests are omitted because Fleet owns its plugin
configuration and launches the bundled source build. The imported file inventory, checksums, Git blob IDs,
commit and tree identity are recorded in [upstream.json](upstream.json).
The upstream README, license, instructions, build scripts and lockfile remain
unchanged. Read the upstream instructions before working with the source.
File checksums follow Git's export attributes, including Windows fixture endings.

The portable loader discovers all five skills directly under `skills/`. Exporting
the development skills from `.agents/skills/` removes one `../` from links to
repository documentation and source. No other instruction or upstream original
is changed. The public skill is produced
at its normal upstream location by `npm run build:cached`.

## New computer

Install separately:

- Python 3.10+ (`python3`). Upstream refresh requires Python with tar extraction
  filters (3.12+, or a maintained 3.10/3.11 security release).
- Node.js and npm using the versions in `../.nvmrc` and `../package.json`.
  See those files for the versions required by the current source revision.
- Codex CLI or Claude Code, signed in, for plugin registration.
- Network access to npm for the first dependency installation.

From the Fleet repository root:

```sh
python3 scripts/setup-rea.py --client codex
```

Use `--client claude` or `--client both` as needed. Setup runs upstream's
`npm ci` and `npm run build:cached`, verifies the actual MCP server, then installs
only `rea@pstack`. It primes only that newly created installation with the verified
build. It refuses any existing REA installation, including disabled ones.
Start a new chat after installation.

To build only Fleet's repo copy, preserving existing installations:

```sh
python3 scripts/setup-rea.py
```

No client configuration, installed/cache copy, running server or peer is changed
in this mode. Build output stays under upstream's ignored `node_modules/`, `dist/`
and cache directories; dependency downloads use this directory's ignored
`.cache/npm`. `HUSKY=0` prevents upstream's dependency preparation from installing
its hooks in Fleet. The upstream build itself is unchanged.

If the supported Node is not on PATH, set the machine-local `FLEET_REA_NODE` to
its executable. npm must be on the resulting PATH. The launcher uses the same
selection and runs upstream `scripts/rea.mjs` directly:

```sh
python3 plugins/rea/fleet/rea.py --version
python3 plugins/rea/fleet/rea.py --help
```

The plugin owns its MCP registration and packaged skills. Do not also run
upstream `rea setup` for the same client/profile; that would create a second
registration. Upstream setup remains available unchanged for standalone use,
including its own preview, approval and provider setup behavior. Use upstream
doctor and tool help for task-specific readiness.

## Refresh upstream

From Fleet's root:

```sh
python3 scripts/update-rea.py --ref <upstream-tag-or-commit>
python3 scripts/setup-rea.py
python3 scripts/verify.py --full
```

The refresh fetches upstream into a temporary Git repository and exports the
selected revision. It first refuses locally modified upstream files or skill
copies. It replaces only inventoried upstream files, removes upstream deletions,
refreshes the development skills and records the new provenance. Fleet manifests
and helpers are preserved. Known upstream distribution manifests are omitted;
other new upstream paths colliding with Fleet packaging block refresh.
The normal source build then regenerates the public skill. No hand-maintained
upstream patches or alternate compiler recipe are involved.

Run `python3 scripts/update-rea.py` without `--ref` to verify the import without
fetching or changing files. Review the diff, bump the plugin version, commit and
push after validation. Refresh/build does not migrate installed copies. Fleet-wide
sync does refresh them; defer it while other projects need the older installation.

## External analysis tools

The source build installs REA's locked npm dependencies. It does not install
external engines, platform SDKs or licenses:

| Target | Separate prerequisites |
| --- | --- |
| Native binaries | Supported Ghidra + Java, licensed Hopper, or supported IDA setup |
| Android | Full JDK and supported JADX/headless bridge |
| Apple runtime/device work | Appropriate Xcode/Command Line Tools, LLDB and device/simulator access |
| Live browser/Electron | Installed runtime/browser and an explicitly selected debugging endpoint |
| Packets, firmware, signals, WASM and other providers | Upstream's documented tools and host requirements for that provider |

Optional upstream submodule references are recorded in `upstream.json`; their
external repositories are not bundled or needed for the ordinary source build.
Consult [upstream installation](../docs/installation.md) for exact provider
requirements. This package is tested on macOS; native Windows artifacts require
the separate upstream build procedure. No hosted web/mobile MCP service is added.
